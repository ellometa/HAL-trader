# Phase 1 — Project Scaffolding + Gemini Smoke Test

## Goal

A runnable repo skeleton managed by `uv`, with secret loading wired
up, and a one-shot script that proves the user's `GEMINI_API_KEY`
works by making a real call to Gemini 2.5 Flash and printing the
response. Push the initial commit to
`https://github.com/ellometa/HAL-trader.git`.

## Context (what exists going in)

Empty `HAL/` directory except for `plans/`. The user has Python 3.11+
and their `GEMINI_API_KEY` in clipboard.

`uv` must be installed (`brew install uv` if missing — check first
with `uv --version`).

## Locked decisions (do NOT re-ask)

- Dep manager: **uv + pyproject.toml**. No `requirements.txt`.
- Version pinning: **compatible-release (`~=`)** in `pyproject.toml`.
- Notes file location: `backend/notes.md` (gitignored).
- Push to GitHub at end of phase: remote
  `https://github.com/ellometa/HAL-trader.git`, branch `main`.

## Step-by-step prompt

You are bootstrapping a Python project called HAL. Working directory
`/Users/ellometa/code/Experimenting/HAL`. Currently contains only
`plans/`.

1. Check `uv --version`. If missing, ask the user to run
   `brew install uv` and pause.
2. Create `.gitignore` first (before `.env`, so the secret is never
   tracked even momentarily).
3. Create `.env.example` with three empty keys.
4. Ask the user to paste their `GEMINI_API_KEY`. Create `.env` with
   that key set; leave `NOTION_TOKEN` and `NOTION_ROOT_PAGE_ID`
   blank. Verify with `git check-ignore .env` after git init.
5. Create `pyproject.toml`. Use compatible-release pins (`~=`).
   The Gemini SDK MUST be `google-genai`, NOT `google-generativeai`.
   If you find yourself typing `import google.generativeai`, stop —
   that's the wrong package.
6. Run `uv sync`. This creates `.venv/`, writes `uv.lock`, installs
   everything. Verify with `uv run python -c "import google.genai"`.
7. Create `backend/config.py`. Use `python-dotenv`'s `load_dotenv()`.
   Resolve `.env` relative to the repo root (use `pathlib.Path(__file__).parent.parent / '.env'`)
   so it works regardless of CWD. Raise
   `RuntimeError("GEMINI_API_KEY missing from .env")` if absent.
8. Create `backend/hello.py`. New SDK pattern:
   ```python
   from google import genai
   from backend.config import GEMINI_API_KEY
   client = genai.Client(api_key=GEMINI_API_KEY)
   resp = client.models.generate_content(
       model="gemini-2.5-flash",
       contents="Say hi in 5 words.",
   )
   print(resp.text)
   ```
   Run with `uv run python -m backend.hello` from repo root.
9. Write the minimal README.
10. Initialize git and push:
    ```
    git init
    git add .
    git status   # confirm .env NOT staged
    git commit -m "phase 1: scaffolding + gemini smoke test"
    git branch -M main
    git remote add origin https://github.com/ellometa/HAL-trader.git
    git push -u origin main
    ```
    The repo on GitHub must already exist (user has created it).
    If the push fails because the remote is non-empty, pause and
    surface the error — don't force-push.

## Acceptance criteria

- `uv run python -m backend.hello` prints a 5-ish-word greeting from
  Gemini. Exit code 0.
- `uv run python -c "from backend.config import GEMINI_API_KEY; print(len(GEMINI_API_KEY))"`
  prints a positive integer.
- `git check-ignore .env` prints `.env` and exits 0.
- `git log` shows one commit on `main`, and the GitHub repo has it.
- `grep -r "google.generativeai" .` returns nothing.
- `uv.lock` is committed.
