# Concrete undo candidates

Specific pieces of current code most worth re-examining. Ordered by
"if I had a free afternoon and wanted to make HAL noticeably better."

Each entry: **what** to undo, **why**, **what to replace it with**,
**effort** in hours.

---

## 1. `_State` class singleton in `backend/main.py`

**What.** A module-level class with `notes` and `client` attributes,
mutated at lifespan startup, asserted-non-None throughout.

**Why undo.** Once journaling lands, `_State` grows to hold a DB
connection pool, a request log, a cache. The class becomes a junk
drawer. Also the `assert _state.client is not None` line is a tell
that the type system isn't carrying its weight.

**Replace with.** A `Deps` dataclass passed via FastAPI's `Depends`.
Each endpoint receives exactly the things it needs. No singletons.

```python
@dataclass
class Deps:
    notes: str
    gemini: genai.Client
    db: sqlite3.Connection  # added in journaling

async def get_deps() -> Deps: ...
```

**Effort.** 2 hours including tests. Low risk. Pure refactor.

## 2. Notes-as-one-flat-file

**What.** `backend/notes.md`, full-overwrite, fully-injected.

**Why undo.** Three reasons:
- Hides the structure of the notes from the prompt (Gemini sees one
  giant wall).
- Prevents per-section iteration (e.g. "show me what 'Module 6 OTE'
  has").
- Makes ingest_notion.py's careful traversal pointless — it builds the
  tree then collapses it.

**Replace with.** Either:
- (a) `backend/notes/<slug>.md` per Notion page, with a top-level
  `notes/_toc.md` rebuilt on ingest. Cheap, future-proof.
- (b) SQLite table `notes(page_id PRIMARY KEY, title, content, parent_id)`.
  Required anyway for retrieval-based prompting if that day comes.

Either way, the *prompt assembly* changes: include the TOC always,
include full sections that match (TF-IDF over the query) up to a
budget.

**Effort.** ~4 hours for option (a), ~8 for (b). Test impact: zero
(notes aren't currently tested).

## 3. `backend/hello.py`

**What.** The phase-1 Gemini smoke-test entrypoint.

**Why undo.** It's been dead code since phase 4. Discoverability hit
("is this how I should test things?"). Worth keeping if you write a
README explaining what it's for; not worth keeping if you don't.

**Replace with.** Delete. Move the connection-test logic into a
`scripts/smoke_gemini.py` if you ever miss it.

**Effort.** 5 minutes. Verify no imports reference it (they don't).

## 4. `extension/icons/`

**What.** Three solid blue PNGs generated by stdlib. Placeholders.

**Why undo.** Visual identity matters more than it should. The
phase-8 P16 polish item already flags this.

**Replace with.** HAL 9000 red eye. Three sizes (16/48/128). A few
minutes in any vector editor, save as PNG via export. Or pay someone
$5 on Fiverr.

**Effort.** 30 minutes if doing it yourself.

## 5. Symbol detection's title fallback

**What.** `symbolFromTitle()` in content.js. Regex over
`document.title`.

**Why undo.** It hasn't fired once in real usage — `?symbol=` is
always present on TV chart URLs. The regex is a phantom safety net
that exists to make the code feel robust without actually being
exercised.

**Replace with.** Delete the fallback. If URL parsing fails, surface a
clean "couldn't detect symbol" error. Less code, more predictable
failure mode.

**Effort.** 15 minutes including manual verification across 5 chart
types.

---

## 6. `MAX_HISTORY = 50` in `chrome.storage.local`

**What.** Hard cap on per-chart history size. Older messages dropped.

**Why undo.** Two reasons:
- 50 messages on a busy chart is half a day's conversation. It silently
  truncates context the user might want.
- It's the wrong location for history once journaling exists — see
  `02_data_and_state.md` Alt 1.

**Replace with.** Once server-side history lands: remove the cap;
storage is cheap. Until then, raise to 200.

**Effort.** 1 minute (cap raise). The bigger move ties to the data/state
plan.

---

## 7. `default=str` in `json.dumps(features, …)`

**What.** Lazy serializer for unknown types. Quietly converts pandas
Timestamps to strings.

**Why undo.** It was helpful in phase 2 when we didn't know what types
the detectors might produce. Now we know. The detectors call
`.isoformat()` themselves; `default=str` is unused on a clean run.

**Replace with.** Drop the parameter. If something blows up, catch the
specific case and convert at the detector boundary, not the
serializer.

**Effort.** 5 minutes + smoke test.

---

## 8. CORS regex as a literal in `main.py`

**What.** A multi-line regex string with two `://` schemes and a host.

**Why undo.** Hard to test, hard to read, hard to evolve when you add
a sixth allowed origin.

**Replace with.** A list of compiled patterns. Or — simpler — just
list the explicit origins:

```python
allow_origins=[
    "http://localhost:8000",
    "http://localhost:3000",
    "https://www.tradingview.com",
    "https://tradingview.com",
]
```

CORS regex was useful when the extension ID was unknown. It's now known
(per Chrome instance), and "chrome-extension://*" is permissive
anyway. The explicit list is shorter, greppable, and surfaces the
trust boundary in the source.

**Effort.** 30 minutes including a smoke test from the extension and
from curl.

---

## 9. The CORS regex's `chrome-extension://.*`

**What.** Allows *any* chrome extension to call HAL.

**Why undo.** It's a personal-machine tool and content-script fetches
use `https://www.tradingview.com` as origin anyway — the
chrome-extension match has never been exercised. Until/unless a
background script needs to call HAL, this is a hole.

**Replace with.** Pin to the specific extension ID once stable, or
remove entirely.

**Effort.** 15 minutes. Mostly verifying nothing breaks.

---

## 10. `notes_block = notes.strip() or "<no notes ingested yet>"`

**What.** Empty-notes fallback in `build_system_prompt`.

**Why undo.** It was a phase-1 affordance. Notes have existed for two
phases now. The fallback hides a real bug ("why is HAL ignoring my
notes?") — silent placeholder vs. loud "no notes loaded, refusing to
analyze" failure.

**Replace with.** Refuse to start if `notes.md` is empty or absent.
Direct user to run `scripts/ingest_notion.py`. Make the failure modes
loud.

**Effort.** 15 minutes. Slightly opinionated — if you intentionally
sometimes run HAL without notes, keep the current behavior.

## What NOT to undo

Listing for the same reason as `new_plans.md`'s "deliberately not"
section — to free you from second-guessing.

- **Vanilla JS in the extension.** See `03_frontend_viz.md` Alt 2/3.
- **FastAPI.** It earns its weight. The next-smallest option is
  Starlette directly; saves 0 lines.
- **`google-genai` SDK.** It's the new official one. Don't downgrade.
- **`uv` as the package manager.** Faster, friendlier than Poetry,
  drop-in for pip.
- **The phase 2 detector definitions** (3-candle FVG, swing-N order
  blocks). They match the standard ICT definitions and have tests.
  Tweak parameters via the proposed P13 toggles, don't rewrite.
- **SSE for streaming.** WebSockets buys nothing; chunked plain text
  loses the event tagging that meta+token+done provides.

## Suggested undo session order

If you sit down for a 4-hour cleanup pass:

1. (5 min) Delete `backend/hello.py`.
2. (15 min) Delete the title fallback in `symbolFromTitle`.
3. (15 min) Tighten the CORS regex to a list.
4. (15 min) Remove `default=str` from the features serializer.
5. (15 min) Lock in "fail-loud on empty notes."
6. (2 hr) Refactor `_State` to a `Deps` dataclass + FastAPI Depends.
7. (≤ 30 min) Push, restart backend, retest the full extension flow.

Bigger items (notes-as-files, server-side history) deserve their own
session and a real plan.
